# Bots 团队插件 · 愿景

本文件说明这个插件**是什么、为谁做、按什么取舍**。使用说明见 README；安全边界见 `SECURITY_MODEL.md`；设计决策见 `DESIGN.md`。

## 是什么

一个跑在 DeepSeek Harness（DSH）里的**常驻 Bot 团队工作台**：用户创建 Bot，和它们 1:1 或群聊协作；每个 Bot 有独立身份、工作区、记忆与运行记录；队长可以把活派给成员，成员交付文件，整个过程在 DSH 侧栏面板里可见、可审、可回放。

它不是：另一个模型、一个多租户 SaaS、一个 IM 网关、一个浏览器/电脑自动化的总控台。

## 为谁做

- 已经在用 DSH、希望把「单次对话」升级为「长期团队」的个人用户/小团队。
- 重视本地数据、不想为几个 Bot 另起一套服务器或桌面应用的人。
- 需要「看得见的派工、交付物、审批与记忆」的人，而不是只想要一个 Agent 框架的开发者。

## 十条核心要求

1. **DSH 原生**：不另装应用/服务，插件在现有 DSH 里工作；只用文档化插件 API，不 patch DSH。
2. **本地优先**：数据在 `~/.dsh`，无云端账户/数据库；卸载不删用户数据。
3. **常驻身份**：Bot 有名字、角色、指令、模型、工作区、权限，跨对话保持。
4. **房间即工作台**：1:1 与群聊都是房间；对话、任务、交付物、审批在同一时间线可见。
5. **派工可追踪**：谁被派了什么、做到哪、交了什么，用户和队长都能看到；不硬卡交付，但缺文件必须可见。
6. **人的决定权**：权限、审批、目标授权、清空/删除等破坏性动作由用户拍板；Bot 不能自己提权。
7. **记忆可控**：记忆可看、可改、可删、可撤销（设置面板 2026-11-08 移除，引擎保留）；消息里的可识别密钥形状不落明文（形状脱敏，不含精确值管理）；清空消息默认保留记忆，用户可显式勾选清空。
8. **长任务可靠**：重启/崩溃/审批中断后能恢复或明确失败，不假装成功；停止策略可解释。
9. **可回放**：运行记录（run/ledger）持久、可导出；排障不靠猜。
10. **轻量可维护**：TS + 包拆分 + 纯函数测试；不为了功能数牺牲可维护性。

## 取舍原则

- **广度让位于纵深**：优先把「房间/派工/交付/审批/记忆」做可靠，不铺 IM/浏览器/电脑操控/Office/多平台桌面。
- **用户的规则不静默推翻**：改变既有产品行为必须显式确认并在 CHANGELOG 记录。
- **证据优先**：每个修复/特性有测试与可观察事实；「看起来没问题」不算完成。
- **模型可理解**：错误、拒绝、提示给模型和用户都写清楚「为什么/下一步」。

## 谁定方向

维护者定方向、设计变更与发布；其他人可以提 issue/PR。大功能请在 PR 描述中写清目标、行为变化与验证方式。
